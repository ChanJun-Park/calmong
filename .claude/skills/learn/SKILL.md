# /learn — 작업 학습 노트 생성

세션에서 함께 진행한 작업을 사용자가 나중에 혼자서 재현할 수 있도록 학습 문서를 만든다.

## 실행 절차

1. **대상 식별**
   - 인자가 없으면: 직전에 마무리한 의미 있는 작업 단위(가장 최근에 끝낸 한 가지 작업)를 대상.
   - 인자가 있으면(예: `/learn dependabot`): 그 키워드/주제에 해당하는 작업만.
   - 단순 잡담·확인 응답은 제외. **학습 가치 있는 행동만**: 파일 편집·명령 실행·구성 변경·결정 사항.

2. **주제 분해**
   - 작업을 의미 있는 단위로 묶는다 (예: "build-logic 스캐폴드", "Spotless plugin 등록", "Detekt 설정").
   - 한 작업이 너무 크면 여러 문서로 나눠도 됨. 너무 잘게는 쪼개지 말 것.

3. **파일 작성**
   - 경로: `.learning/<오늘 날짜 YYYY-MM-DD>/<topic-slug>.md`
     - 날짜는 세션 컨텍스트의 `Today's date` 사용 (절대 추측 금지)
     - `topic-slug`은 영문 kebab-case (예: `spotless-detekt-setup.md`)
   - 같은 날 여러 개 추가 가능. 디렉토리가 없으면 생성한다.

4. **인덱스 갱신**
   - `.learning/INDEX.md`가 있으면 새 항목 한 줄 추가:
     `- YYYY-MM-DD [제목](경로) — 한 줄 요약`
   - 없으면 새로 만들고 헤더 + 첫 항목.

5. **사용자에게 회신**
   - 만든 파일 경로와 다룬 주제 목록만 짧게 보고. **문서 본문 전체를 다시 출력하지 말 것**.

## 문서 구조

각 학습 문서는 아래 골격을 따른다.

````markdown
# <한 줄 제목 — 핵심 작업>

> 작성일: YYYY-MM-DD
> 관련 커밋: <hash> (없으면 생략)
> 목표: <왜 이 작업을 했는가, 한두 문장>

## 한눈에 보기
- 무엇을 했나 (3~5 불릿)
- 결과물 (생성·수정된 파일/디렉토리/원격 상태)

## 1. <주제 1 제목>
### 배경 / 왜
- 이 단계가 왜 필요했나, 어떤 선택지가 있었나, 왜 그걸 골랐나

### 무엇을 했나
- 구체 행동: 파일 경로, 명령어, 핵심 코드 블록

### 직접 해보기
1. <순서대로 따라할 단계>
2. ...

### 알아두면 좋은 점
- 변형·트레이드오프·관련 공식 문서 링크

## 2. <주제 2 제목>
(같은 구조 반복. 주제가 하나뿐이면 이 섹션은 생략)

## 핵심 명령어·파일 모음
복습용. 명령어와 파일 경로만 코드 블록에 모아둠.

## 함정 / 주의
이번에 실제 부딪힌 에러·우회 과정·미해결 항목. 없으면 생략.
````

## 작성 원칙

- **순서는 why → what → how**. 결정 과정을 이해해야 다른 상황에 응용 가능.
- 명령어·파일 경로는 **그대로 복붙해 실행 가능하게** 정확히. 추상화 금지.
- **실패한 시도·우회 과정도 솔직히 기록** — 같은 함정에 재차 빠지지 않도록 (예: "처음엔 `compileOnly`만 썼는데 런타임 에러 → 루트에 `apply false` 추가로 해결").
- **한글 작성** (프로젝트 컨벤션 [[feedback-korean]]에 따름). 기술 식별자는 영어 유지.
- **"실제로 한 것"의 기록**이지 일반 베스트 프랙티스 가이드가 아니다. 임의로 다른 도구를 추천하거나 다른 길로 다시 쓰지 말 것. 사용자가 내린 결정·선택은 그대로 보존.
- 코드 블록은 핵심 라인만. 파일 전문은 경로로 링크.

## 하지 말 것

- 학습 가치 없는 잡담·확인 응답·자잘한 재시도까지 다 적기
- 거대한 코드/로그 덤프 (요지만 + 파일 경로 링크)
- 사용자에게 응답을 요구하는 섹션 추가 (학습 노트는 단방향)
- 회신 메시지에서 문서 본문 통째 재출력
- 날짜를 추측하거나 시스템 외부에서 끌어오기 (세션의 `Today's date`만 사용)

## 인덱스 파일 (`/.learning/INDEX.md`) 포맷

처음 만들 때:

````markdown
# Learning Notes 인덱스

calmong 프로젝트를 함께 만들며 배운 것들의 모음.

## 2026

- 2026-05-31 [Spotless·Detekt 셋업](2026-05-31/spotless-detekt-setup.md) — convention plugin으로 lint 통합
````

연도 헤더는 필요해질 때 추가. 최신이 위로 오도록 정렬.
